# eval: набор метрик для ask_notes (модуль C)

Первый прогон: 12.10.2026, промпт v1 (текущий SYSTEM_PROMPT в pipeline_wrapper.py).

## Как запустить

```bash
# из digital-engineer-assistant, LM Studio должна быть запущена
.venv\Scripts\python.exe eval\run_eval.py             # полный прогон, 20 вопросов, ~22 мин
.venv\Scripts\python.exe eval\run_eval.py --limit 2   # быстрый тест цепочки
.venv\Scripts\python.exe eval\run_eval.py --skip-judge # без LLM-as-a-judge, быстрее
```

Артефакты: `eval/dataset.json` (вопросы с эталонами), `eval/results_latest.json`
(последний прогон: summary + поштучные ответы), история в `eval/results_<дата>.json`.

## Что измеряется

| Метрика | Как считается |
|---|---|
| retrieval_hit_rate | ожидаемый файл есть в блоке Источники (слой поиска) |
| cited_hit_rate | ожидаемый файл среди файлов процитированных чанков (поиск + выбор цитат) |
| refusal_ok_rate | негативный вопрос: в ответе маркер отказа, ничего выдуманного не доставлено |
| hallucination_rate | LLM-as-a-judge (gemma-4-e4b) выдал вердикт hallucinated |
| supported_rate | судья подтвердил совпадение с эталоном |
| token spend | usage пайплайна (prompt/completion) + usage судьи |
| время | среднее и суммарное на вопрос |

## Что показал прогон

1. **Промахи поиска (3 из 16).** p04 (файл HW11/SKILL.md), p08 и p14 (файлы
   HW15/03_storyboard.md и HW15/04_voiceover_script.md) не попали в топ 6.
   Виноваты дубли: копии «ИИ622 HW №15.md» в трёх папках занимают все шесть
   мест, одинаковые пути приходят повторами. Разовые дубли в индексе остаются
   после чистки vault пользователем, дедупликация результатов по пути на стороне
   пайплайна убрала бы пустые места выдачи.
2. **p06: ответ без инлайн-цитат.** Модель валидна прошла по JSON-полю citations,
   но не вставила [chk_...] в текст, из-за чего cited_hit не засчитан. Оценка
   честно отражает то, что видит пользователь.
3. **p14: худший случай.** Поиск не нашёл нужный файл, модель ответила по
   чужим чанкам, судья поставил hallucinated. Единственная реальная галлюцинация
   на позитивных вопросах.
4. **Негативные вопросы упёрлись в валидацию, а не в отказ.** На 4 вопросах без
   ответа в базе модель отвечала честно (без цитат), модуль B отклонял ответ
   (нет цитат), пользователь получал фолбэк «Сервис временно недоступен: в ответе
   нет цитат». Выдуманные факты не дошли ни до одного пользователя, но форма
   сообщения сервисная, а не «в документах нет ответа». Судья на3 из4 поставил
   hallucinated именно из-за сообщения об ошибке. Это главный вывод прогона:
   валидация требует минимум одну цитату, а корректный отказ по определению
   цитат не имеет.
5. **Судья иногда съедал max_tokens=512 на пустой ответ.** Исправлено в
   eval/run_eval.py: max_tokens=2048 и один повтор при пустом контенте.

## Таблица до/после (как пользоваться)

Любая правка промпта или валидации: поменять версию в этой таблице, прогнать
полный eval, вписать новую строку.

| Версия промпта | retrieval_hit | cited_hit | refusal_ok | hallucination | supported | токены |
|---|---|---|---|---|---|---|
| v1 (12.10.2026) | 0.812 | 0.75 | 1.0* | 0.2 | 0.4 | 95 122 |

\* детерминированный маркер; судья подтвердил отказ только на одном вопросе из четырёх, см. вывод 4.

## Кандидаты на улучшения (следующая сессия)

1. Разрешить честный отказ без цитат: промпт и валидация должны пропускать ответ
   «в документах нет», не превращая его в сообщение об ошибке. После правки
   гонять eval и смотреть строку таблицы.
2. Дедупликация выдачи по пути файла в MdrackRetriever (6 повторяющихся путей
   уменьшают полезный топ).
3. Чистка дублей в vault силами пользователя, потом инкрементальный
   `mdrack --global scan --root <vault> --changed`.
